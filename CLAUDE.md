# Stock Alerts

Stock alert system that screens tickers by fundamentals and spots opportunities through two rules: current price vs. the analysts' price target (`AnalystAlerts`) and price drops over several time windows (`PriceAlert`). It runs daily at 14:00 (mainland Spain time) via GitHub Actions.

## How to run

```bash
# Backend: from the repo root, with the venv active
cd src && python main.py
```

```bash
# Frontend: generate the data first with the command above
npm --prefix web install && npm --prefix web run dev
```

The GitHub Actions workflow runs `python main.py` with `working-directory: src`, so every import is relative to `src/`.

## Project structure


## Architecture

- **Hexagonal**: `providers/base.py` defines the `DataProvider` interface (ABC). `YFinanceProvider` is the concrete adapter. `DataProviderImpl` composes the adapters and adds loading tickers from JSON.
- **One source, N sinks**: `pipeline.run_pipeline()` computes and returns a `Snapshot` (a dataclass with `screened`, `analyst_alerts`, `price_alerts`) with no side effects. Consumers format it: `notifications/` into text for the email, `export/` into JSON for the web.
- **Alerts return data, not text**: `BaseAlert.run()` returns a `DataFrame` enriched with `short_name`. Subclasses only implement `apply_rules()`. No formatting inside `alerts/`.
- **Main flow**: `main.py` → `run_pipeline()` → `export_json()` + (when there are alerts) `format_snapshot()` → `send_email()`.
- **Contract with the web**: every file in `web/public/data/` is `{"generated_at": <ISO>, "rows": [...]}`. The frontend depends on that shape, not on the Python code.
- **Ingestion scripts** (`src/scripts/`): run manually to refresh `data/`. Not part of the main flow.

## Frontend architecture (`web/`)

- **Charting libraries stay encapsulated**: `DataGrid.tsx` is the only file that imports AG Grid; `Chart.tsx`, the only one that imports ECharts. Pages only use `<DataGrid>` and `<Chart>`. Switching library = touching one file.
- **`lib/` is the boundary with the data**: `types.ts` mirrors the columns Python exports; `data.ts` concentrates the `fetch` and the `useData` hook. If the data ever comes from an API, only `data.ts` changes.
- **Pages (`routes/`) know neither where the data comes from nor how a grid is painted**: they declare columns, call `useData` and compose.
- **New page**: a file in `routes/` + a `<Link>` and a `<Route>` in `App.tsx`.
- **New column**: add it to the DataFrame in Python → to the type in `types.ts` → to the page's column array.
- **HashRouter**, not BrowserRouter: GitHub Pages returns 404 when reloading normal routes.

## Conventions

- **Everything in the repository is written in English, with no exceptions**: variable, class and function names, comments, docstrings, log and error messages, commit messages, documentation, the text the user sees on the web (titles, column `headerName`, loading and error messages), URL routes, and the alert email.
- Type hints on every function signature.
- Imports relative to `src/` (not absolute from the repo root).
- Paths to data files use `Path(__file__).resolve().parents[N] / "data"` so they are independent of the working directory.
- The frontend code must be simple, and explained well enough for someone who knows nothing about React, TypeScript, Vite or web development. When you use one of those features, explain it at the top of the file or function in a comment. For example, if you use a React hook, explain what it does and why you use it.

## Environment variables

Backend — defined in `.env` (local) or GitHub Secrets (CI):
- `GMAIL_USER`: Gmail address used to send
- `GMAIL_APP_PASSWORD`: 16-character App Password
- `ALERT_TO`: alert recipient (optional, defaults to GMAIL_USER)

The frontend does not need environment variables for now.

## Dependencies

Backend:
- `yfinance`: market data (price targets, fundamentals, statements)
- `pandas`: DataFrames throughout the data flow
- `requests`: Wikipedia scraping (index tickers)
- `python-dotenv`: loads `.env` locally

Frontend:
- `react` + `react-router-dom`: UI and routing
- `ag-grid-community` / `ag-grid-react`: tables (free version, MIT). No pivoting or row grouping: those are paid Enterprise features. If they were ever needed, the only change is the `registerModules` call in `DataGrid.tsx`.
- `echarts`: charts
- `vite` + `typescript`: build and typing
